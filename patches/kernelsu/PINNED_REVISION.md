# Pinned KernelSU revision

A KernelSU build clones the upstream repository at a fixed revision and wires
it into the kernel tree. The build never follows a moving branch.

| Field | Value |
| ----- | ----- |
| Repository | `https://github.com/tiann/KernelSU.git` |
| Ref | `v3.3.0` |
| Commit | `932014ab5b2c9b74a3d11e2ec4d17dd10fc9442e` |
| Release date | 2026-08-28 |

`scripts/ci/lib/kernelsu.sh` holds these values in `KERNSU_URL`, `KERNSU_REF`,
and `KERNSU_COMMIT`. The integration resolves `KERNSU_COMMIT` after the clone
and fails the build when the checked-out commit differs from it, so a moved
upstream tag cannot silently change the kernel.

KernelSU is not vendored into this repository; only the pinned revision is
recorded here. KernelSU is licensed under GPL-2.0.

## Wiring

The integration performs the same three steps as upstream `kernel/setup.sh`,
without the `git stash`, `git pull`, and branch checkout that script performs:

1. `drivers/kernelsu` becomes a symlink to the cloned `kernel/` directory.
2. `drivers/Makefile` gains the line `obj-$(CONFIG_KSU) += kernelsu/`.
3. `drivers/Kconfig` gains `source "drivers/kernelsu/Kconfig"` immediately
   before its last `endmenu`.

Each step is skipped when it is already present, so the integration can run
again on a tree that already carries it.

## Configuration

`gaokun3_defconfig` supplies `CONFIG_EXT4_FS`, but not the rest of what
KernelSU needs:

- The `KSU` Kconfig entry depends on `KPROBES`, which the defconfig leaves
  unset.
- The syscall hook calls `register_trace_prio_sys_enter()` whenever
  `CONFIG_HAVE_SYSCALL_TRACEPOINTS` is set, which is true on arm64. The
  tracepoint headers only define that function when `CONFIG_TRACEPOINTS` is
  set, and the defconfig disables tracing (`# CONFIG_FTRACE is not set`).
  `TRACEPOINTS` and `TRACING` have no prompt, so `CONFIG_FTRACE` is enabled to
  select them.
- `CONFIG_SECURITY_SELINUX` is already enabled. KernelSU includes
  `security/selinux/include/objsec.h`, whose `flask.h` is generated by building
  `security/selinux/` during a normal kernel build.

`olddefconfig` drops an unmet tristate without an error, so a KernelSU build
enables `CONFIG_KPROBES`, `CONFIG_FTRACE`, and `CONFIG_KSU` in the generated
`.config` before `olddefconfig` runs, and afterwards fails the build when
`.config` does not end up with `CONFIG_KSU=y`, `CONFIG_KPROBES=y`, and
`CONFIG_TRACEPOINTS=y`.

## Updating

Change the commit in the table above and the defaults in
`scripts/ci/lib/kernelsu.sh` in the same commit, then run a full package build
and confirm `CONFIG_KSU=y` in the produced `kernel-out/.config`.
